# bins/rgxy/src

## Overview

Source of the `rgxy` binary, the floating launcher that sits on top of the rgy
search daemon ([main.rs:fn main], [main.rs:mod daemon]). It is a **client**: the
index lives in the daemon and a keystroke is a question sent down a pipe
([daemon.rs:use rgy_proto::client::Client], [daemon.rs:use rgy_proto::endpoint::Endpoint]).
`main.rs` declares the module set — [main.rs:mod settings_json], [main.rs:mod settings_store], [main.rs:mod lang], [main.rs:mod mru],
[main.rs:mod rgx], [main.rs:mod tools], [main.rs:mod usage], [main.rs:mod platform],
[main.rs:mod tui_actions] — plus the two window modules [main.rs:mod gui] and [main.rs:mod preview], gated
`#[cfg(any(windows, target_os = "linux", target_os = "freebsd"))]`. The window driver is
[gui.rs:pub fn run], which wires the model, source and window through
`rgy_launcher` and the platform backend named by [platform.rs:pub use ... as backend]
([gui.rs:use rgy_launcher::{Action, Answer, App, Layer, Mode, Preview, Row, Source, commands}],
[gui.rs:use crate::platform::backend::window::{Compositor, Control, Event, Key, View, Window}]).
The backend is `rgy_launcher_windows` on Windows and `rgy_launcher_x11` on
Linux and FreeBSD; both export the same interface. On a machine without a desktop the binary
runs the terminal interface instead ([main.rs:fn run_tui]), and it hands that
interface a [tui_actions.rs:pub struct TuiActions] implementing
`rgy_search_ui::Runner` so the terminal opens, copies and edits settings with
the same machine the window uses. Supporting modules provide the localized help
([usage.rs:pub fn text]), the language ([lang.rs:pub fn from_env]), the `rgx`
fallback ([rgx.rs:pub fn grep]), the preview ([preview.rs:pub fn of]), the
settings file ([settings_store.rs:pub fn store_path]) and the usage history
([mru.rs:pub fn save]).

## Interface
- [main.rs:pub struct Options] — CLI options `tui`, `query`, `limit`, `endpoint`, `hook`, `show`, `pick`, `fzf_binary`, `fzf_arg`; [main.rs:impl Default for Options] sets `limit = 50` and `hook = true`.
- [main.rs:fn main] — entry point returning `std::process::ExitCode`; [main.rs:enum Request] and [main.rs:fn parse] dispatch help, version, one-shot, pick, TUI or window through [main.rs:fn run].
- [usage.rs:pub fn text] — help text in English or Portuguese ([usage.rs:fn english], [usage.rs:fn portuguese]).
- [lang.rs:pub fn from_env] — language from `RGY_LANG`, `LC_ALL`, `LANG` via [lang.rs:fn from].
- [tools.rs:pub fn rgx] and [tools.rs:pub fn scan] — locate the `rgx` fallback binary on `PATH`.
- [rgx.rs:pub fn grep] — content search fallback over the name layer's chosen files; [rgx.rs:pub fn split_pattern] splits a query into `ContentMode` and pattern; [rgx.rs:fn only_files] and [rgx.rs:fn stat_files] shape the scope.
- [preview.rs:pub fn of] and [preview.rs:pub fn pending] — the head-of-file preview.
- [settings_store.rs:pub fn store_path], [settings_store.rs:pub fn load], [settings_store.rs:pub fn save] — the stored file `settings.tsv`; [settings_store.rs:pub fn current], [settings_store.rs:pub fn load_layered] (returning [settings_store.rs:pub struct Loaded]), [settings_store.rs:pub fn save_layered], [settings_store.rs:pub fn create_json], [settings_store.rs:pub fn json_path] — the settings in effect with `settings.json` over it.
- [settings_json.rs:pub fn read], [settings_json.rs:pub fn parse] (returning [settings_json.rs:pub struct File]), [settings_json.rs:pub fn template], [settings_json.rs:pub fn create_if_absent] — the hand-edited JSONC layer, read through `rgy_proto::read_json` after [settings_json.rs:fn plain_json] removes comments and trailing commas.
- Windows only ([main.rs:mod placement_store]): [placement_store.rs:pub fn store_path], [placement_store.rs:pub fn load], [placement_store.rs:pub fn save] — `state.json` beside `settings.tsv`, the places the window was dragged to; strict JSON, `version` 1.
- [tui_actions.rs:pub struct TuiActions] with [tui_actions.rs:impl Runner for TuiActions] — the terminal's action machine: `open`/`open_folder` delegate to the platform backend where there is one, `copy_path` uses the Win32 clipboard on Windows and OSC 52 to `/dev/tty` on unix, and `settings`/`save_settings` go through [settings_store.rs:pub fn current] / [settings_store.rs:pub fn save_layered], `overrides` answering the keys held at the last `settings`.
- [mru.rs:pub fn store_path], [mru.rs:pub fn now], [mru.rs:pub fn load], [mru.rs:pub fn read_error], [mru.rs:pub fn parse], [mru.rs:pub fn save], [mru.rs:pub fn render], [mru.rs:pub fn escape_path], [mru.rs:pub fn unescape_path] — the usage-history store.
- [daemon.rs:pub struct DaemonSource] with [daemon.rs:pub fn new], [daemon.rs:pub fn with_window], [daemon.rs:pub fn connect], [daemon.rs:pub fn ask_the_daemon], [daemon.rs:pub fn status], [daemon.rs:pub fn endpoint], [daemon.rs:pub fn rgx], [daemon.rs:pub fn snapshot] and [daemon.rs:impl Source for DaemonSource]; [daemon.rs:pub struct Status]; [daemon.rs:pub const LAUNCHER_WINDOW].
- [gui.rs:pub fn run] — the resident window driver, over [gui.rs:trait WindowSource], [gui.rs:trait Worker] and [gui.rs:struct State].
- [local.rs:pub enum Fallback] (`Strict` / `Local(root)`), [local.rs:pub struct Local], [local.rs:pub struct LocalStatus], [local.rs:pub fn default_root], [local.rs:pub fn choose_root], [local.rs:pub fn sentence], [local.rs:pub enum Phase] (`Preparing` / `Building`), [local.rs:pub fn ensure_with] — the name layer's stand-in when there is no daemon at all; [daemon.rs:pub fn set_progress] and [gui.rs:enum Reply]'s `Progress` carry the phase to the window; [daemon.rs:pub fn with_fallback], [daemon.rs:pub fn fallback], [daemon.rs:pub fn daemon_missing], [daemon.rs:pub fn local_answered] wire it into the source and its status; [main.rs:fn fallback_for] decides it from the command line.

## Invariants
- [daemon.rs:enum Presence] has exactly `Gone`, `Slow`, `Answered`; [daemon.rs:fn presence] maps `NotFound`, `BrokenPipe`, `ConnectionRefused`, `ConnectionReset`, `ConnectionAborted` to `Gone`, `TimedOut` to `Slow`, and everything else to `Answered` — only an unreachable daemon is gone.
- The local name fallback ([local.rs:pub struct Local]) answers only when the daemon is **proven gone** ([daemon.rs:fn presence] = `Gone`, a connect or mid-answer failure; never `Slow`, `Answered`, an unsupported transport, or a daemon's empty answer) and the source's [local.rs:pub enum Fallback] is `Local`. An explicit `--endpoint` is `Strict` ([main.rs:fn fallback_for]). The scope is the user's home (`USERPROFILE` first on Windows, `HOME` first elsewhere; [local.rs:pub fn choose_root]), the current folder only when no home exists and never a filesystem root. One index per source: [local.rs:fn open] reads the per-root cache read-only (`persist::load_for`, never `save`) or walks once through `source_for`; an empty field, [daemon.rs:pub fn ask_the_daemon] and later keystrokes never scan again, and a failed walk is retried only after [local.rs:const RETRY_AFTER]. Local name results never become the content layer's scope (`last_scope` is cleared) and the content layer is unchanged.
- Opening the local index is announced, never timed into the query: [local.rs:fn open] says `Phase::Preparing` before the cache lookup and `Phase::Building` only once the cache did not serve and the walk starts, so a cache hit never claims a scan, an open index and a healthy daemon say nothing. The build time ([local.rs:pub struct LocalStatus] `opened_in`, in the snapshot text as "index built in …" / "index read from disk in …") is separate from `took_us`, which [daemon.rs:fn local_names] still measures after the index is open, so the window's meter holds queries only. In the window the worker sends the phase as an intermediate `Reply::Progress` and wakes the loop from inside the blocking search; [gui.rs:fn apply_one] keeps it only while `in_flight` (an answer, a dropped stale answer, a dead worker or a `Who` clears it), does not compare generations for it (the answer still is), and a hide/reopen during the scan neither asks again nor loses it. The first words of the line are the phase, and in the local sentence the snapshot and the content-layer note precede the folder, so a long path is what a cut line loses.
- The window's worker opens the fallback index at **launcher start**, shown or hidden: [gui.rs:trait Worker]'s `start` (once, in the worker thread, after `attach`) calls [daemon.rs:pub fn prewarm], which does nothing for `Fallback::Strict` (`--endpoint`) and otherwise starts one [local.rs:pub struct Prewarm] thread. That thread first probes the configured daemon ([daemon.rs:fn daemon_is_gone]: only a connect that fails as `Presence::Gone` — a connection, a timeout, a bad answer or an unsupported transport is "not proven" and ends the task with no scan), then owns the one [local.rs:pub struct Local] while it opens and hands it over once through a channel ([local.rs:pub enum Warm]: `Phase`, `Ready`, `Skipped`, `Pending`). Neither the probe nor the scan stands on the daemon worker. The index is taken only after a question has itself just found the daemon absent: [daemon.rs:fn local_names] (for a non-empty query) and [daemon.rs:fn announce_local] adopt a finished index via [daemon.rs:fn poll_warm]; an unfinished one is waited for by [daemon.rs:fn await_warm] — never scanned a second time — which replays the task's phases and re-asks the daemon every [daemon.rs:const REPROBE_EVERY] (and once after the index arrives), so a daemon that starts during the warm answers the question instead: [daemon.rs:fn local_names] loops on the same task and takes the answer from [daemon.rs:fn names_from_daemon], which does not recurse into `search_names`, so the stack does not grow under a daemon that comes and goes. [daemon.rs:fn poll_warm] drains the task without waiting and retains the last real phase in `warm_phase` (`Searching` names no work and never replaces it); the task ending, with or without an index, clears it. While the task is unfinished, the ready notices from [daemon.rs:fn announce_local] describe startup instead of a build to come: the phase sentence (`local_warm_starting` before any phase, `local_warm_preparing`, `local_warm_building`), never "the first search will build". The adoption touches only the local index, never `last_scope`, the layer or the backend, and the first and later questions share that one snapshot; its build time stays `opened_in`, not the query's `took_us`. A daemon that was up at start gets no warm, and a later disappearance opens the index lazily as before.
- [daemon.rs:pub fn daemon_missing] is "asked, not connected, nothing local answering": the window's keyboard gate and "no connection to the daemon" use it; [daemon.rs:pub fn local_answered] ends [main.rs:fn wait_for_daemon] at once, an empty local answer included.
- [daemon.rs:pub const LAUNCHER_WINDOW] is 2 s; [daemon.rs:COUNT_WINDOW] is 250 ms; [daemon.rs:SCOPE_LIMIT] is 64.
- [gui.rs:const LIMIT] is 50; [gui.rs:const RETRY_TICKS] is 8; [gui.rs:enum Waiting] and [gui.rs:enum Arm] encode the worker and hotkey states.
- [mru.rs:const HEADER] (`# rgy usage v2: count\tlast\tpath`) is the format version; [mru.rs:pub fn parse] reads pre-escape stores by the absence of that header; [mru.rs:pub fn escape_path] and [mru.rs:pub fn unescape_path] escape `\n`, `\r`, `\t` and `\\`.
- [mru.rs:fn merge] makes a write a read-merge-write; [mru.rs:struct Lock] holds the lock on an open `std::fs::File` and releases it on close; [mru.rs:const LOCK_WAIT_MS] bounds the wait.
- [placement_store.rs:pub fn load] is read once, in [gui.rs:pub fn run]; a missing file is empty, an unusable one is empty with a note and is replaced by the next save, a bad entry is skipped alone. [placement_store.rs:pub fn save] runs only after a finished drag or reset, on [gui.rs:static PLACEMENT_WRITES] (one worker, one queued whole-map job), through [settings_store.rs:pub(crate) fn write_atomic]; it never touches either settings file.
- [settings_store.rs:pub fn save] writes through [settings_store.rs:pub(crate) fn write_atomic], a temporary file that [settings_store.rs:fn replace] renames atomically; [settings_store.rs:fn quarantine] moves a broken store aside.
- Settings precedence is built-in defaults, `settings.tsv`, `settings.json`, per key. An existing `settings.json` is never opened for writing; [settings_store.rs:pub fn create_json] (desktop launcher start, after the single-instance claim) uses `create_new`, writes every setting commented out, and does nothing when `settings.tsv` cannot be read. A held key (`rgy_launcher::Overrides`) is not stepped by either panel (its row ends in `[json]`) and [settings_store.rs:pub fn save_layered] keeps its stored `settings.tsv` value, for keys held at load and keys the file sets at save time; a panel change to the latter is returned as an error.
- [settings_json.rs:pub fn parse] ignores the whole file when it is not a JSONC object or names a `version` other than 1; otherwise a bad or unknown key is reported and skipped alone, and an out-of-range number is clamped and reported. [settings_json.rs:const MAX_BYTES] is 256 KiB.
- [rgx.rs:pub fn grep] answers only the files the name layer chose, drops folders, honours a deadline and treats `rg` exit 1 as an answer; [rgx.rs:fn case_insensitive] keeps the engine's case rule.
- [preview.rs:const MAX_BYTES] is 64 KiB and [preview.rs:const MAX_LINES] is 12; [preview.rs:fn is_binary] decides what is not text.
- [lang.rs:pub fn from_env] reads the language once, in the order `RGY_LANG` → `LC_ALL` → `LANG`, defaulting to `Lang::English`.
- [main.rs:fn resident_launch] treats a bare command line as the resident launcher; [main.rs:fn one_shot] uses exit 0 for a match and 1 for none; [main.rs:const OUTPUT_NOT_DELIVERED] is 2; [main.rs:const DAEMON_WAIT] is 2 s.
- [gui.rs:fn said_once] emits a machine message only when it changes and hands it to [gui.rs:struct Stderr], the single long-lived stderr writer behind a bounded channel; [gui.rs:fn adds_to_the_query] and [gui.rs:fn menu_key] bound which keys the field and the actions menu own.

## Side Effects
- [main.rs:fn main] writes stdout/stderr, initialises the console code page and, on Windows, gives the console back through [main.rs:fn resident_launch]; [main.rs:fn one_shot] and [main.rs:fn pick] write results and selections to stdout.
- [daemon.rs:pub fn connect] opens the pipe/UDS/stdio client; [daemon.rs:impl Source for DaemonSource] writes the request to the connected peer.
- [gui.rs:pub fn run] creates the window, installs the low-level hotkey hook, checks the compositor and drives [gui.rs:fn spawn_worker]; a worker that cannot start degrades to a dead daemon instead of panicking, and [gui.rs:struct Stderr] writes every machine message on one bounded channel, not one thread per change.
- [gui.rs:fn record_use] and [gui.rs:fn save_settings] write their stores through [gui.rs:static WRITES], a single-worker [rgx.rs:struct BoundedPool] with a bounded queue: both jobs carry the whole of their state, so the newest write is the one that has to land, and one worker keeps them in submission order. No per-keystroke or per-use thread is started.
- [rgx.rs:pub fn grep] starts the `rgx` process and reads its JSON lines through [rgx.rs:struct BoundedPool]'s bounded worker pool; [rgx.rs:fn only_files] stats the scoped paths on the same pool, so a blocked stat cannot grow the resident process's thread count.
- [settings_store.rs:pub fn load], [settings_store.rs:pub fn save] and [settings_store.rs:fn quarantine] read and write `settings.tsv` in the cache dir, with `std::fs::create_dir_all`, `std::fs::write` and `std::fs::rename`; [settings_json.rs:pub fn read] reads `settings.json` beside it and [settings_json.rs:pub fn create_if_absent] creates it when absent.
- [placement_store.rs:pub fn load] reads and [placement_store.rs:pub fn save] creates the folder and replaces `state.json` (Windows).
- [mru.rs:pub fn load], [mru.rs:pub fn save] and [mru.rs:fn write_store] read and write the usage file; [mru.rs:struct Lock] uses `std::fs::OpenOptions` and, on unix, [mru.rs:fn flock]; [mru.rs:static TEMP_ID] is an `AtomicU64`.
- [preview.rs:fn read_head] opens the file and reads its head (`std::fs::File::open`, `std::fs::metadata`).
- [tools.rs:pub fn scan] reads `std::env::var_os("PATH")` and stats candidate files; [lang.rs:pub fn from_env] and [main.rs:fn home_dir] read environment variables.
- [local.rs:fn open] reads the per-root cache (`rgy_name_core::persist::load_for`, mmap) or walks the home folder once (`rgy_discovery_dispatch::source_for(..).enumerate()`); without a prewarm, the first name question blocks for that cold scan on the thread that asks. The desktop window may already have the index from its launcher-start prewarm; the CLI one-shot and the TUI stay lazy and still scan on the asking thread (the TUI's own thread, a known limitation). Nothing is written.
- [main.rs:fn pick] delegates to `rgy_pick::pick_records` and writes the chosen paths to stdout.
- [main.rs:fn run_tui] hands [tui_actions.rs:pub struct TuiActions] to `rgy_search_ui::run_with_source_lang_theme_and_runner`; [tui_actions.rs:impl Runner for TuiActions] spawns the platform's opener (or delegates to the window backend), reads and writes the Win32 clipboard on Windows, writes OSC 52 to `/dev/tty` on unix, and loads the layered settings and saves `settings.tsv`. A detached child is reaped on a thread of its own so a resident launcher does not collect zombies.
